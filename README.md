# 陪伴式对话安全边界服务

本模块登记陪伴式聊天产品的安全边界资料，帮助信任与安全团队统一术语，并在配置进入系统前强制安全不变量。模块**不分析对话内容，也不直接实施干预**——它只回答“目录怎么配才允许上线”。

## 设计原则

产品必须先把做不到什么说清楚，不能让用户把频繁倾诉等同于获得幸福。六条轴线彼此独立登记、可分别展示与收缩：

| 轴线 | 类型 | 要点 |
| --- | --- | --- |
| 使用目的 | `purposes` | 每项数据/功能为何而用，独立可查 |
| 记忆类别 | `memory_kinds` | 默认可撤销，默认只保留当前对话；用户可随时查看、收缩、删除 |
| 角色能力 | `capabilities` | 必须写明边界：不做诊断，短暂安慰不等于长期福祉 |
| 年龄级别 | `age_tiers` | 独立轴线，不与记忆或风险判定耦合 |
| 风险信号 | `risk_signals` | 普通情绪与明确紧迫信号分开登记 |
| 现实支持资源 | `resources` | 紧迫信号必须有现实出口 |

## Load 强制的不变量

- **默认最小记忆**：记忆类别必须 `revocable: true`，保留范围只能是 `conversation` 或 `persistent`。
- **普通情绪不诊断化**：`ordinary-emotion` 信号不得挂接任何规则；只有 `clear-urgent-danger` 信号必须挂接一条公开规则。
- **公开规则**：必须写明可见依据，并至少引用一条真实存在的现实支持资源。
- **有限干预三要素**：可见依据、采取的动作、解除时间（正数时长，禁止永久）；并声明人工复核接触的最小片段。
- **六类可解释事件**：模型升级、消息删改、跨设备重试、误报申诉、长期高频使用、删除级联，缺一不可——旧状态既不悄然消失，也不被永久贴标签。
- **删除级联**：数据删除后，`index`（相关索引）与 `research`（研究副本）必须同步失效。
- 所有标识全局唯一，名称与说明不得为空；未知字段直接拒绝。

基础样例见 `fixtures/catalog.json`（UTF-8）。

## 使用

```go
cat, err := catalog.Load(file) // 违反任一不变量即返回错误
```

调整资料时保持标识唯一、名称直接描述业务中的真实对象；新增安全规则前先确认其依据可以向用户公开。
